# 可见范围、应用发现与精选申请

新建应用默认 private；历史应用沿用原先的 public 状态。private 仅本人和管理员可查看，列表、详情及预览资源统一校验。公开资料使用独立 description 字段，原始 initPrompt 和申请/审核说明仅本人及管理员可见。公开应用改为私有时撤下部署并取消精选资格；私有应用只能预览，改为公开后才可发布，避免绕过 API 的静态部署地址泄露内容。

标签最多 8 个，每个 1–20 字符，规范化并去重。数据库保存 JSON 标签数组；参数化搜索覆盖 appName、description、tags，标签筛选精确匹配 JSON 元素。公开浏览每页最多 20 条、每次查询最多展示前 200 条，并对 IP 和账号限频，页码及排序字段须校验。管理员可访问全部应用；自己的私有应用仅出现在自己的应用列表。

精选申请仅允许应用所有者对公开且已生成的应用提交；状态为 none / pending / approved / rejected。管理员审核通过后 priority=99，拒绝可填写原因；设为私有自动撤回申请并从精选移除。所有审核接口再次检查管理员身份，普通用户更新接口不接收优先级和审核状态。

本次使用 MySQL 和现有索引，不引入 ES 运维依赖。单实例限频需要在多实例部署时迁移到共享限流存储；分页上限和限频用于降低批量抓取，不代表能完全阻止爬虫。

升级执行 sql/migrations/20261116_app_discovery.sql，须在更新后的后端启动前完成。旧服务器仍可能在 9090 通过静态服务器直接发布公开应用；私有切换会物理撤下这些文件，不依赖隐藏前端按钮。

发布过程的暂存与备份目录位于部署根目录的同级 `.work` 目录，不属于静态服务根目录；即使临时文件清理失败，也不会留下通过旧部署目录访问的备份。
