# 应用删除与关联清理

普通用户和管理员删除入口共用同一服务。保留应用表原有逻辑删除语义，清空其初始描述、封面和部署信息，并物理删除 app_version 版本记录。文件清理覆盖该应用所有支持生成类型的代码目录、封面、历史快照及部署目录，不按用户提供的封面链接删除其他文件。

删除与生成、回退、部署互斥。正在生成或切换版本时拒绝删除，提示用户先停止生成再试，防止删除后后台继续产生文件。版本操作通过数据库行锁与删除协调。

删除前将关联目录移入 tmp/app_cleanup/{UUID}，写入只含应用 ID 和部署标识的恢复清单。数据库事务失败时恢复目录；提交成功后清空暂存目录。物理清理失败会保留任务，每分钟重试，重启后也能继续。恢复时检查应用的实际删除标记，未提交的任务恢复文件，已提交的任务只清理暂存文件。活跃任务不参与后台恢复。

提交结果不明确（例如数据库提交成功但连接中断）时先核对持久化删除标记，不会直接恢复已删除应用的线上文件；无法连接数据库时保留任务，等待后续确认。

清理路径从受控根目录和已验证的应用 ID、部署标识构建，不接受清单里的任意绝对路径；目录遍历不跟随符号链接。不存在的目录可直接跳过。这里只处理用户新发起的删除及其失败任务，不扫描删除旧的孤立目录。

当前项目没有独立聊天历史表。以后增加关联表时，须同时加入删除事务；应用封面在生成目录和快照内随目录清除。

无需增加数据库字段或执行迁移。回归测试覆盖删除权限、重复删除、生成互斥、暂存失败、事务回滚、清理重试及重启恢复；Windows 目录联接测试需要允许创建目录联接的运行环境。隔离 SQL 验证使用内存数据库和新建临时目录，不删除现有应用。
