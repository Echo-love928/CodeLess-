# 应用体验与生命周期

实施范围：管理员列表显示用户昵称；精选确认框仅显示居中的“是否设为精选应用？”；新建应用时使用 AI 从初始需求生成简短名称，超时或失败回退到描述摘要。

生成状态：pending（待生成）、generating（生成中）、completed（已完成）、stopped（已停止）、failed（失败）。历史数据先标记 unknown，在后端启动时根据生成目录恢复状态。应用生成期间禁止重复启动。刷新页面可读取状态并停止正在进行的生成；页面退出取消连接也取消模型流。停止不保存不完整代码，不覆盖上一版预览。生成状态以文件成功保存为依据，封面失败不影响代码生成。

停止方案：使用每个应用独立的取消信号，取消传递到 LangChain4j StreamingHandle；不能仅关闭浏览器连接。首个模型事件前没有句柄，记录取消意图，收到句柄立即取消。当前服务按项目现有单实例架构实现；多实例部署需共享任务路由。

部署方案：online / offline 状态与生成状态分开；暂停时删除发布目录，保留源代码、封面和部署标识，重新发布复用原地址。只允许应用所有者生成、停止、部署、暂停。验证部署路径在固定根目录下。

实施顺序：后端取消适配与生命周期测试；状态字段和 SQL 增量迁移；控制接口和 AI 命名；前端状态展示、停止与上下线操作；前后端构建与回归验证。

验证重点：停止到达模型句柄、首个 token 前停止、重复生成、失败后重试、越权、下线保留源代码、路径越界、旧数据兼容、Snowflake ID 字符串精度。

发布与下线会先切换发布目录，再保存数据库状态；数据库保存失败则恢复原来的线上文件。列表和聊天页只在存在生成任务时轮询状态，页面退出时清理计时器。

上线前先执行 sql/migrations/20261115_app_lifecycle.sql，再重启后端。脚本可重复执行，并兼容仅缺少其中一个字段的数据库；已有状态不会因重复执行被重置。已有自动化测试中调用真实 AI、数据库和浏览器的集成测试需要相应服务可用。

如果启动报 `Unknown column 'generationStatus' in 'field list'`，说明应用代码已更新，但当前连接的数据库还没有执行上述迁移。只修改 create_table.sql 不会更新已存在的 app 表；应在后端实际连接的 CodeLess 数据库执行迁移，再启动后端。
